# Gemini Prompt

A minimal web app: type one prompt, press **Send**, get one answer generated by
**Gemini CLI** on your Ubuntu server (signed in with your own Google account), or
by the **official Gemini API** with an API key.

- `frontend/` – React + TypeScript + Tailwind (Markdown rendering, copy, clear, light/dark, mobile-friendly)
- `backend/` – Node.js + Express: `POST /api/generate`, `GET /health`, `GET /api/config`
- `Dockerfile`, `docker-compose.yml` – production container
- `deploy/` – Nginx example and systemd unit for native installs
- `deploy.sh`, `update.sh`, `healthcheck.sh` – helpers

Tested with Gemini CLI **0.65.0** (`gemini -p "<prompt>" --output-format json`).

---

## 1. How it works

```text
Browser ──HTTPS──> Nginx ──> Express (127.0.0.1:3000)
                               │  validate, auth, rate-limit, queue
                               └─ spawn("gemini", ["-p", prompt, "--output-format", "json"])   (no shell)
                                  or Gemini API (@google/genai)
```

- The prompt is passed as one argument to `child_process.spawn` with `shell: false`; it is never interpreted by a shell.
- Each CLI run happens in a fresh empty temp directory, so the CLI cannot see the app's files.
- At most `MAX_CONCURRENT_REQUESTS` CLI processes run at once; up to `MAX_QUEUE_SIZE` more wait; extra requests get "server busy".
- Timed-out runs get `SIGTERM`, then `SIGKILL` 5 s later, sent to the whole process group.
- Identical prompts from the same IP that are still running are rejected (409). The Send button is also locked while a request is running.
- Errors show a clear message plus a code, HTTP status and technical details (exit code and Gemini CLI output, with API keys/OAuth tokens redacted). Prompts are not logged (`LOG_PROMPTS=false`).

### API

```http
POST /api/generate
Content-Type: application/json

{ "prompt": "Explain HTTPS simply" }
```
Success: `{ "success": true, "response": "..." }` · Error: `{ "success": false, "error": "Readable message" }`

Status codes: 400 invalid, 409 duplicate, 413 too long, 422 blocked by safety filters,
429 rate limit/quota, 502 provider failure/malformed output, 503 auth broken / CLI missing / busy, 504 timeout.

`GET /health` → `{"status":"ok","provider":"cli","uptime":12,"queue":{...}}`

## 2. Access control and Google terms (read this)

- **No access code:** anyone who can open the site can send prompts using your Gemini account and quota. Keep the site private (firewall, VPN, or Nginx basic auth) or use `GEMINI_PROVIDER=api` for public use.
- **For a public site use `GEMINI_PROVIDER=api`** with a Gemini API key from <https://aistudio.google.com/apikey>, keep the rate limits, and follow the Gemini API terms.
- End users never enter Google credentials. OAuth tokens and API keys stay on the server and are never sent to the browser.

## 3. Quick start (Docker, recommended)

### 3.1 Server prerequisites (Ubuntu 22.04 / 24.04)

```bash
sudo apt update && sudo apt install -y ca-certificates curl unzip openssl
# Install Docker Engine + Compose plugin
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER" && newgrp docker
docker compose version
```

### 3.2 Extract and configure

```bash
mkdir -p ~/apps && cd ~/apps
unzip ~/gemini-prompt.zip            # creates ./gemini-prompt
cd gemini-prompt
cp .env.example .env
chmod 600 .env
nano .env                            # review provider, limits, etc.
```

### 3.3 Build and start

```bash
./deploy.sh                          # or by hand:  mkdir -p gemini-auth && sudo chown 1000:1000 gemini-auth && docker compose up -d --build
```

### 3.4 Sign in to Gemini CLI inside the container (one time, CLI provider only)

The image contains Gemini CLI but **no credentials**. They are stored on the host in
`./gemini-auth/`, which is mounted at `/home/node/.gemini`. It is never copied into the image.

```bash
docker compose exec -it -e NO_BROWSER=true app gemini
```
1. Pick **Login with Google**.
2. The CLI prints a URL. Open it in a browser on **any** computer, sign in with your authorized Google account, and paste the code back into the terminal.
3. When you see the chat prompt, type `/quit`.

Check it:
```bash
docker compose exec app gemini -p "Say hello" --output-format json
```

**Other option:** sign in on your laptop with `npx @google/gemini-cli`. Then copy
`~/.gemini/oauth_creds.json` (and `settings.json`, `google_accounts.json`) to the server's `./gemini-auth/`
with `scp`, and run `sudo chown -R 1000:1000 gemini-auth && chmod 700 gemini-auth`. Treat these files as passwords.

If `./deploy.sh` finds an existing `~/.gemini` on the host, it copies it in for you.

### 3.5 Daily commands

```bash
docker compose up -d --build     # start / rebuild
docker compose stop              # stop
docker compose down              # stop and remove container (credentials in ./gemini-auth stay)
docker compose logs -f app       # logs
./healthcheck.sh                 # health check
./update.sh                      # rebuild after updating the code
./update.sh --cli                # also upgrade Gemini CLI to latest
```
To pin a CLI version: `GEMINI_CLI_VERSION=0.65.0 docker compose build`.

## 4. Native install (no Docker)

Use this if you prefer Gemini CLI to run directly on the host with your normal `~/.gemini` login.

```bash
# Node.js 22 LTS
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
# Gemini CLI
sudo npm install -g @google/gemini-cli
gemini --version
# Sign in once as the user that will run the service
NO_BROWSER=true gemini          # choose "Login with Google", open the URL elsewhere, paste the code, then /quit
gemini -p "Say hello" --output-format json      # must print JSON with "response"

cd ~/apps/gemini-prompt
./deploy.sh --native            # npm ci, builds the frontend, installs + starts the systemd service
```

Manual equivalent:
```bash
(cd frontend && npm ci && npm run build)
(cd backend && npm ci --omit=dev && npm start)     # serves frontend/dist + API on 127.0.0.1:3000
```

Service commands: `sudo systemctl status|restart|stop gemini-prompt` · logs: `journalctl -u gemini-prompt -f`
Update: `./update.sh --native` (add `--cli` to upgrade Gemini CLI).

## 5. Using the Gemini API instead

In `.env`:
```ini
GEMINI_PROVIDER=api
GEMINI_API_KEY=your-key-from-aistudio
GEMINI_API_MODEL=gemini-2.5-flash
```
Then run `docker compose up -d` (or `sudo systemctl restart gemini-prompt`). You do not need `gemini-auth/`.
The page header shows which provider is active ("Gemini CLI" or "Gemini API").

## 6. Domain + HTTPS with Nginx

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/gemini-prompt
sudo sed -i 's/example.com/your.domain.com/g' /etc/nginx/sites-available/gemini-prompt
sudo ln -s /etc/nginx/sites-available/gemini-prompt /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d your.domain.com          # free Let's Encrypt cert + auto-renew
sudo ufw allow OpenSSH && sudo ufw allow 'Nginx Full' && sudo ufw enable
```
First point your domain's DNS **A record** at the server IP. The app itself only listens on `127.0.0.1`.
Keep `proxy_read_timeout` longer than `GEMINI_TIMEOUT_MS`.

## 7. Configuration reference

| Variable | Default | Meaning |
|---|---|---|
| `GEMINI_PROVIDER` | `cli` | `cli` or `api` |
| `GEMINI_COMMAND` | `gemini` | CLI binary name or absolute path |
| `GEMINI_TIMEOUT_MS` | `120000` | Time limit per request |
| `GEMINI_MODEL` | – | Passed as `--model` |
| `GEMINI_APPROVAL_MODE` | `plan` (in example) | Passed as `--approval-mode`. Leave it empty for older CLIs |
| `GEMINI_API_KEY` / `GEMINI_API_MODEL` | – / `gemini-2.5-flash` | API provider |
| `MAX_PROMPT_CHARS` | `8000` | Longest prompt allowed (also shown in the page counter) |
| `MAX_BODY_SIZE` | `64kb` | Largest JSON request body |
| `MAX_CONCURRENT_REQUESTS` / `MAX_QUEUE_SIZE` | `2` / `10` | Process limit and wait queue |
| `RATE_LIMIT_WINDOW_MS` / `RATE_LIMIT_MAX` | `60000` / `10` | Requests per IP per time window |
| `CORS_ORIGINS` | – | Extra allowed origins, comma-separated |
| `TRUST_PROXY` | `loopback` | Express trust proxy (correct client IPs behind Nginx) |
| `LOG_PROMPTS` | `false` | Log prompt text (off by default) |

## 9. Troubleshooting

| What you see | Fix |
|---|---|
| "Gemini authentication failed on the server" | The CLI is not signed in or the token expired. Docker: `docker compose exec -it -e NO_BROWSER=true app gemini`. Native: run `NO_BROWSER=true gemini` as the service user. Check that `./gemini-auth` is owned by uid 1000. |
| "Gemini CLI is not installed" | Native: `sudo npm i -g @google/gemini-cli` and check that `which gemini` is in the service `PATH` (set `GEMINI_COMMAND=/full/path/gemini`). Docker: rebuild. |
| "Gemini returned output that could not be read" / unknown argument | Your CLI version is too old or too new. Run `gemini --help` and confirm that `-p` and `--output-format json` exist. Upgrade with `./update.sh --cli`. If `--approval-mode plan` is rejected, clear `GEMINI_APPROVAL_MODE`. |
| "quota or rate limit was reached" | Your Google account's free or paid Gemini limit is used up. Wait, use another model, or switch to `GEMINI_PROVIDER=api`. |
| "took too long" | Raise `GEMINI_TIMEOUT_MS` (and Nginx `proxy_read_timeout`). |
| "server is busy" | Raise `MAX_CONCURRENT_REQUESTS` / `MAX_QUEUE_SIZE` if the server has spare CPU and RAM. |
| API provider errors | Check `GEMINI_API_KEY` and that the Generative Language API is enabled for the key's project. |
| 502 from Nginx | The app is down. Run `./healthcheck.sh` and look at the logs. |

Manual test from the server:
```bash
curl -s http://127.0.0.1:3000/api/generate \
  -H 'Content-Type: application/json' -d '{"prompt":"Say hello in 3 languages"}'
```

## 10. Security notes

- Never commit `.env` or `gemini-auth/`. Both are in `.gitignore` and `.dockerignore`.
- The container runs as a non-root user, with a read-only filesystem, all capabilities dropped, and a process limit.
- Secrets are only read from environment variables on the server. The frontend bundle has no keys, hostnames or CLI details.
